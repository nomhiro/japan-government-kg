これは実装前のUIモックです（レビュー用）

「一般ユーザが日本政府の状態を把握しやすくするには？」という問いへの答えとして、 画面を2層に分けました。上のタブで行き来できます。

  • 第1層「全体を見る」＝把握する層。23府省の予算額を金額順に並べた1画面。 府省は誰でも名前を知っていて23個しかないので、無名ノードのグラフより速く伝わります。
  • 第2層「つながりを辿る」＝探索する層。グラフはここが主役。 グラフは探索の道具であって把握の道具ではない、という判断です。
  • 検索窓は両方の層に常設で、常に「絞り込み／中心を移す」操作です（別の一覧に切り替わりません）。

数字はすべて実測値です（架空の政府データは1件もありません）

  • 府省別の予算額・件数: data/artifact/2026-08-28-d2-recipient-category-v2/kg.nq（884,053行）の全走査
  • グラフのノードと関係: 本番API /neighborhood/budget/2025/2840?depth=2 が返した57ノードを、読みやすさのため28に間引いたもの
  • 「型の地図」の件数: 同じ成果物の全走査。実現していない関係は描いていません
  • 「支出の総額を出さない理由」の実例: 5-1_RS_2025_支出先_支出情報.csv（193,912行）の全走査

いちばん重要な発見（裁定B96 → B97で撤回 → B98/B99で裏づけ）

予算額 123.1兆円に対し、支出の記録を全部足すと 156.8兆円。33兆円合いません。 最初は「足す行為そのものが成立しない」と結論しました（裁定B96）。 それは誤りでした——5-2 支出先_支出ブロックのつながりに 資金の流れが有向辺として、入口が真偽値として書いてありました（裁定B97）。 重複29.9兆円を除いた額が出せます。

その方式が正しいことは、方式の外から確認しました（裁定B98）： 流れの計算に一切使っていない執行額という列と突き合わせると、 裁定B20が挙げた「比が正確に2.0/3.0になる245事業」のうち243事業が比1.0に直り、 執行額との完全一致が1,488→3,075事業に倍増しました。総額も0.086%で一致します。

  • 支出の記録はお金の流れの図で、「支出先ブロック」ごとに段階が分かれています。 同じお金が段階ごとに何度も記録されます（実例: 児童手当の 1,401,293,745,413円 が 「国→市町村」と「市町村→受給者」の2ブロックに同額で入る）。
  • しかもブロックの意味は事業ごとに違う——並列の区分・流れの段階・お金の出どころの どれでもあり得ます（JICAの事業では「財政融資資金借入金」というブロックがあり、これは支出ではなく借入）。 機械的に正しい総額を出す方法が存在しません。
  • 加えて、支出額はそもそも前年度の執行実績です（コード内の既測記録B19）。当初予算と年度も基準も違います。

→ 合計してよいのは予算額だけ（1事業1年度に1値、重複なし）。第1層はこれだけを使っています。 画面上の「支出の総額を出していないのはなぜ？」を開くと、この説明が実例つきで出ます。

作りながら実データで見つかった問題（未決のもの）

  • 支出の表示名が支払先の法人名そのもの（skos:prefLabel）。 隣の法人ノードと同じ文字列が並びます（28ノード中8件が重複）。モックでは表示側で金額を主ラベルにしましたが、 データ層で「金額（支払先）」に変えるほうが正しいかもしれません。どちらで直すか。
  • 未解決参照は skos:prefLabel を持たないため、いまの本番アプリでは「(表示名なし)」と描かれます。 モックでは unresolved_text（元の記述）を表示名にしました。
  • 1事業の中の資金の流れは、本当は描けるはずで、いま描けません。 ブロック（段階）はとても分かりやすい絵になります（国→1,741市町村→7,789,939人の受給者）。 しかしKGがブロック番号を持っていないので、描くにはデータ層の追加が必要です。未着手。

レビューで決めたいこと

  • 2層に分ける構成でよいか。既定で開くのは「全体を見る」にしてあります（元の要求は「初期表示をグラフに」でしたが、 一般ユーザの把握には帯グラフのほうが速いと判断しました）。グラフを既定に戻すこともできます。
  • 帯グラフの目盛り。線形だと厚労省が449px・他は2〜30pxで互いに比較できません（実測）。 「厚生労働省を除いて見る」で取り直せるようにしましたが、対数目盛りは採りませんでした （集中している事実が静かに消えるため）。これでよいか。
  • 上の「未決」3件をどう直すか。うち資金の流れのデータ層追加は完了しました （裁定B97。KGにExpenditureBlockが入り、CQ12が実データで 126,911,742,219,947円を返すことを確認済み）。残りは支出・未解決参照・ブロックの 表示名の重複をデータ層で直すか表示側で直すか。
  • 5年分の予算と執行を出すこの形でよいか（裁定B99）。帯の全体を歳出予算現額に したのは、当初予算を全体にすると執行率が100%を超えて見えるからです （2021年度は当初107.1兆に対し執行128.1兆）。
  • 「国が自ら支払った額」を第1層に出すこと自体の可否。ずれる要因が両方向に あるので、数字を1つ大きく出すより執行率（83.7〜87.0%）のほうが安全かもしれません。
  • 絞り込みは「薄くする」方式。一致しないノードを消す方式のほうがよいか。
  • 辺のラベルを常時出すか、選択時だけにするか（いまは選択時＋ホバー時のみ。型の地図では出せるものを出し、 隠れた分は下の表に全部載せています）。

本番との実装上の違い

モックの描画は依存を増やさないための自前SVG＋簡易フォースレイアウトです。 本番はSigma.js（WebGL）で、レイアウトは graphology-layout-forceatlas2 を想定しています （現状の同心円配置からの変更点）。Sigma.jsはCSSを読まないため、ラベル色は settings.labelColor で明示する必要があります——ダークモードで文字が黒く残っていた原因で、 これは既に修正・検証済みです。
