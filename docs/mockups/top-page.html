これは実装前のUIモックです（レビュー用）

  • 表示しているデータは実データです。本番API /neighborhood/budget/2025/2840?depth=2 が返した57ノードを、読みやすさのため28ノードに間引いたもの。架空の政府データは1件も入れていません。
  • 「型の地図」の件数も実測値です。data/artifact/2026-08-28-d2-recipient-category-v2/kg.nq（884,053行）を全走査して数えました。実現していない関係は描いていません——型の地図が「取れるはずのデータ」を約束してしまう問題への答えです。
  • 描画はモック専用の自前SVG＋簡易フォースレイアウトです。本番はSigma.js（WebGL）で、レイアウトは graphology-layout-forceatlas2 を想定しています（現状の同心円配置からの変更点）。
  • ノードのドラッグ・ホイールで拡大縮小・ノードクリック・辺クリック・絞り込み・軸の表示切替は実際に動きます。触って判断してください。

この設計で答えているつもりの要求

  • 初期表示が検索窓だけではなく、いきなりグラフである → 読み込み直後にこの断面が出る
  • 検索語が一覧ではなくフィルターである → 入力すると一致ノードが緑で強調され、それ以外が薄くなる（画面が別の一覧に切り替わらない）
  • 関連性の描画がメイン／ノードクリックで詳細 → 右パネルに型・軸・属性・出典（一次資料URLと取得日）・隣接の内訳が出る
  • ダークモードで読める → 右上の「テーマ」で切り替えて確認できます

レビューで決めたいこと

  • 初期表示は「実データの断面」で良いか（もう一案は「型の地図」を初期にする）。どちらを既定にするか。
  • 府省のようなハブ（実測: 厚生労働省だけで予算事業が29件はみ出す）を、いま「⋯+29」と省略しているが、これで十分か。
  • 絞り込みは「薄くする」方式。一致しないノードを消す方式のほうが良いか。
  • 辺のラベルを常時出すか、選択時だけにするか（いまは選択時＋ホバー時のみ）。
  • このモックを作って実データで見つかった問題。支出エンティティの表示名（skos:prefLabel）が 支払先の法人名そのもので、隣の法人ノードと同じ文字列が並びます（実測: 28ノード中8件が重複）。 モックでは表示側で金額を主ラベルにしましたが、データ層で支出の skos:prefLabel を 「金額（支払先）」に変えるほうが正しいかもしれません。どちらで直すか。
  • 同じくモックで見つかった問題。未解決参照（対応先が特定できなかった記述）は skos:prefLabel を持たないため、いまの本番アプリでは「(表示名なし)」と描かれます。 モックでは unresolved_text（元の記述）を表示名にしました——それが 「何が特定できなかったのか」を示す唯一の手がかりだからです。
