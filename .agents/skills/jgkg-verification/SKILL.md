# JGKG検証

AGENTS.md と docs/codex-development.md の環境・検証コマンドを使う。パスはリポジトリルート基準。
検査の正本は .github/workflows/ci.yml。変更に関わるローカル検査を実施し、PRでは既存CI全体の結果を確認する。
生成→差分確認→テストの順で直列に実行する。型検査を含むビルドを済ませたら同じ型検査を重複実行しない。

実データを扱う場合は接続先のデータセットを確認してから利用者と同じHTTP経路を通す。
UI変更では実ブラウザで操作と画面幅、API未配備や失敗時の表示も確認する。
公開後は配信対象と配備済み応答を突き合わせる。伝播待ちはB107に従う既存verify-site.pyを使う。
取得・公開・サービス起動は依頼で許可された範囲で行い、他プロジェクトのポート・プロセスを奪わない。

結果は実行コマンド、成否、検証対象、実測根拠、未検証範囲を報告する。
テストの緑を実データ・本番確認に読み替えない。失敗・スキップを成功扱いしない。
