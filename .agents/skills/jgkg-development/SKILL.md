# JGKG実装

リポジトリルートの AGENTS.md と docs/codex-development.md を読む。パスはすべてリポジトリルート基準。
対象仕様、関連裁定の後続訂正、実コードを照合し、計画の入力・出力とproducer/consumerの接続を確かめる。
古い計画のモデル名・superpowers呼び出しを実行要件にしない。

変更は専用worktreeで小さな単位に分ける。生成元を直し、生成物を再生成する。
公開URIと出典を保持し、実データにない値を合成しない。
コード変更では再発・境界条件を捉える検査を選ぶ。単なる文書変更に実装をなぞるテストを増やさない。
レビュー指摘を直して検証し、仕様変更の理由・根拠・残件を記録する。
共有ファイル・生成・ブラウザを同時に変更しない。外部公開は依頼の許可範囲に従う。
